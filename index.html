p2jb-devdevdevkit
Same, from pooP2JB-dev. Keeps the console-type picker and is the only split build carrying kstuff-devkit-only.elf, so a kit wants this one. Takes no query flags — its run parameters are baked in.

P2JB standalone — hosted

12.00 – 12.70 · GitHub Pages, no LAN host needed
The same two split p2jb builds as above, published so they run from anywhere. Nothing about the chain changes: the beacon and one-shot latch simply fall back when there is no exploit host behind them, so a static host behaves like the LAN one.
P2JBretail / testkit
12.00 – 12.70, six profiles, each checked against its own retail binary. Jailbroke end to end on hardware — joinRet=0x0 shellcodeRet=0x0, elfldr on :9021. ELF tiles deliver from inside the console, so no server helper is needed.
P2JB-devdevdevkit
Same engine for a kit. Keeps a kit's own 0x81 instead of forcing 0x82, so Release Check Mode still reads Development, and it is the only split build carrying kstuff-devkit-only.elf. Also confirmed on hardware.

Which one is for my console? A devkit needs the devkit site — it sets target ID 0x81 and the debugger auth ID, and offers the devkit kstuff build. Retail and testkit both take the ordinary site: a testkit is close enough to retail here that it wants target ID 0x82, not 0x81. Picking the wrong one just fails to jailbreak — it does not harm the console.
